# GPT Web Codex：中文界面、内嵌 ChatGPT 与引导设计

## 目标

将 Windows 桌面启动器改为默认简体中文的日常控制台，提供浅色、深色和跟随系统主题；在应用内打开一个独立的 ChatGPT 窗口；并以分步骤设置引导帮助用户完成工作区、Skills、本地 MCP、Tunnel 和 ChatGPT 连接器的配置。

本次只改桌面启动器体验。保留当前纯本地 MCP 运行时、工作区边界和受控 Tunnel 监督器，不增加浏览器扩展、DOM 注入、Cookie 导出、对话历史读取、远程 MCP 或通用 shell 执行。

## 参考项目边界

参考的 `gpt-web-codex` 启动器可复用以下模式：

- 把设置过程表示为可恢复、可诊断的步骤状态；
- 由主进程维护外部窗口和状态，渲染器只调用窄 IPC；
- 诊断与日志不返回运行时密钥、Tunnel 凭据或访问令牌；
- 对导航、弹窗和权限请求采取默认拒绝策略。

参考项目刻意不创建内嵌浏览器或 ChatGPT 登录状态。因此，不复制其“无浏览器”行为；本设计新增一个受限的 Electron BrowserWindow，但不复用或导出其会话数据。

## 信息架构与本地化

主窗口默认显示简体中文，设置中保留 English。左侧导航固定为：

1. 主页：运行时、Tunnel 和连接器状态；启动、停止、诊断与“打开 ChatGPT”。
2. 工作区：选择和切换工作区配置。
3. Skills：扫描可用 Skills，设置本工作区的默认项。
4. MCP：仅维护受限的本地 stdio MCP 注册表。
5. 任务与日志：查询受限本地任务状态/输出、取消任务、查看已脱敏日志。
6. 设置与引导：主题、语言、ChatGPT 登录状态、日志和连接向导。

主题可选“跟随系统”“浅色”“深色”。主题值保存在现有私有启动器状态中；应用启动时将其应用于渲染器。浅色主题以白色及低对比中性色为主，深色主题使用现有深色层次但更新为统一的令牌、间距、卡片与状态色。所有文本、空状态、按钮、错误和引导步骤必须本地化；不得以英文内部错误直接充当最终界面文案。

## 独立 ChatGPT 窗口

点击“打开 ChatGPT”创建或聚焦独立窗口，而不是把 ChatGPT 放进主控制台。窗口使用专用持久会话分区，例如 `persist:gpt-web-codex-chatgpt`，使用户可在后续启动时保持其 ChatGPT 登录状态。

该窗口的安全边界：

- `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`，且不加载桌面控制台 preload；
- 不注册任何主进程 IPC，不可访问工作区、Skill、MCP、任务、日志、Tunnel 或凭据；
- 仅允许 HTTPS 顶层导航至 ChatGPT/OpenAI 和必要身份提供商域名；未知导航、下载、权限请求和非白名单弹窗默认拒绝；
- 新窗口必须经过相同的主进程白名单策略，不能让网页自定义 Electron 配置；
- 设置提供“清除 ChatGPT 登录状态”按钮，仅清除该专用分区的 Cookie、缓存和站点存储；不影响主控制台配置、Tunnel 凭据或工作区资料。

登录 Cookie 仅由 Electron 的专用会话存储管理。程序不读取、显示、导出或经由 MCP 传递 Cookie、访问令牌、对话文本或历史记录。

## 设置引导

设置页以可折叠的五步引导显示实际状态而非假定成功：

1. 选择工作区：必须已有有效工作区配置。
2. 配置 Skills 与本地 MCP：Skills 默认值和本地 MCP 注册表均经过现有边界验证；空注册表合法。
3. 检测本地运行时与兼容 Tunnel 客户端：读取 Doctor 的受限状态。未发现兼容客户端时明确显示“需要提供客户端”，不显示已配对或已连接。
4. 打开内嵌 ChatGPT：聚焦受限窗口，并指向 ChatGPT 连接器设置的已允许入口。
5. 验证：运行现有 Doctor 并展示已脱敏结果；仅真实完成的条件可以标记完成。

引导进度持久化为无敏感信息的状态，允许重启后继续。凭据仍只在一次性设置 IPC 中进入主进程并在使用后清空渲染器字段。

## 组件与数据流

主进程新增 `ChatGptWindowController`：创建/聚焦窗口、施加导航和权限策略、清除独立会话数据、关闭窗口及发布不含敏感信息的窗口状态。它只接受固定 IPC 意图，例如 `openChatGpt` 和 `clearChatGptSession`。

现有 profile/controller 为设置引导提供只读状态：工作区是否存在、Skill/MCP 是否有效、Doctor/Tunnel 是否可用。渲染器基于此状态展示步骤与推荐操作，但绝不自行推断 Tunnel 已成功连接。

主题、语言和非敏感引导进度通过现有私有 state store 保存。预加载层只新增明确声明的窗口操作，不暴露 Electron session、任意 URL 打开、任意 IPC 或通用运行时工具调用。

## 错误处理

- ChatGPT 窗口创建或导航失败：主窗口显示简体中文可操作错误，并保留原控制台运行状态。
- 白名单外导航、下载、权限或弹窗：拒绝并写入脱敏诊断事件，不把 URL 查询参数或 Cookie 记入界面。
- 清除登录状态失败：显示失败但不把存储细节泄露给渲染器。
- Tunnel 客户端缺失：引导停在第 3 步，Doctor 显示“不可用”；ChatGPT 窗口仍可用于登录和查看连接器设置。

## 测试与验收

- 主进程测试：独立会话分区、无 preload/Node/IPC、导航/弹窗/下载/权限拒绝、固定允许入口、清除登录状态。
- preload/IPC 测试：只公开固定的打开和清除方法；伪造 sender 与任意 URL 都被拒绝。
- 状态测试：主题、语言、无敏感引导进度恢复正确；默认中文；中英文文案完整。
- 渲染器合同测试：主题切换、中文导航、五步引导状态、Tunnel 不可用提示和 ChatGPT 操作。
- 回归：完整核心与 launcher 测试、类型检查、生产构建、Windows NSIS 打包和从解包应用目录的运行时冒烟检查。

## 非目标

- 不实现浏览器扩展、页面 DOM 注入或侧边栏聊天；
- 不从 ChatGPT 窗口读取或同步对话；
- 不实现或伪造未知 Tunnel CLI 协议；
- 不加入远程 MCP、任意 URL 打开、任意命令执行或浏览器调试端口。
